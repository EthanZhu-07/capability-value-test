# Capability Value Test｜새 기능 가치 검증

[English](README.md)｜[简体中文](README.zh-CN.md)｜[繁體中文](README.zh-TW.md)｜[日本語](README.ja.md)｜**한국어**｜[Русский](README.ru.md)｜[हिन्दी](README.hi.md)｜[Español](README.es.md)｜[Français](README.fr.md)｜[Deutsch](README.de.md)｜[Português](README.pt.md)｜[العربية](README.ar.md)

> 새 기능의 사용 과정을 보이게 하고, 그 기능이 만든 가치를 측정 가능하게 합니다.

Capability Value Test는 AI Agent를 위한 범용 Skill입니다. 새로 연동한 기능(Skill, 모델, 플러그인, MCP Server, 브라우저, 오픈소스 구성요소 또는 Agent 워크플로)이 실제로 호출되었는지, 기존 방식보다 측정 가능한 가치를 만들었는지 검증합니다.

기존 방식과 새 기능을 연동한 뒤의 방식을 공정한 A/B Test로 비교합니다. 실행 전에 사람이 전체 실험 설계를 검토하고 승인하며, 실행 후에는 독립적이고 시각적이며 추적 가능한 HTML 보고서를 생성합니다.

## 답해야 하는 질문

1. **새 기능이 실제로 호출되었는가? 증거는 어디에 있는가?**
2. **실제로 가치가 생겼는가? 그 가치를 정량화할 수 있는가?**
3. **사용 과정과 구체적인 가치를 시각적으로 이해할 수 있는가?**

## 진행 과정

1. 새 기능과 연동 전후의 두 가지 작업 방식을 정의합니다.
2. 두 방식이 모두 수행할 수 있는 실제 작업을 선택합니다.
3. 입력, 환경, 제약, 측정 범위, 평가 기준을 맞춥니다.
4. 전체 실험 설계를 사람에게 제시하고, 거절되면 수정합니다.
5. 명시적 승인 후 두 방식을 실행하고 결과, 지표, 호출 증거를 기록합니다.
6. 차이를 분석하고 HTML 보고서를 생성합니다.

목표는 새 기능을 이기게 하는 것이 아니라, 무엇이 달라졌고 그 증거가 도입을 뒷받침하는지 확인하는 것입니다.

## HTML 보고서

1. **최종 권고**: 도입, 도입하지 않음, 또는 증거 부족. 적합한 상황과 부적합한 상황도 설명합니다.
2. **가치와 효과**: 결과 품질, 작업 완료 시간, Token, 비용, 단계, 오류, 재시도를 비교합니다.
3. **호출 증거**: 마지막 섹션에 두 방식의 명령, 도구 호출, 입출력, 로그, 타임스탬프, 작업 ID 및 상태를 보관합니다.

호스트가 제공하지 않는 지표는 0이 아니라 “사용 불가”로 표시합니다. 민감한 정보는 반드시 제거합니다.


렌더러는 Python 표준 라이브러리만 사용하며 오프라인에서 열 수 있는 단일 HTML 파일을 생성합니다.

## 한계

- 각 방식 1회 실행은 방향성 증거일 뿐 통계적 보장이 아닙니다.
- 두 방식 모두 같은 대표 작업을 완료할 수 있어야 합니다.
- Token과 비용은 호스트가 제공할 때만 비교할 수 있습니다.
- 호출 여부를 검증할 수 없으면 결론은 “증거 부족”이어야 합니다.
- 헤드리스 실행은 실행 기록으로 표시하며 실시간 녹화로 표현하지 않습니다.
