# Capability Value Test｜Проверка ценности новой возможности

> Сделать использование новой возможности видимым, а создаваемую ею ценность — измеримой.

Capability Value Test — универсальный Skill для AI-агентов. Он проверяет, была ли действительно вызвана новая возможность (Skill, модель, плагин, MCP Server, браузер, компонент с открытым исходным кодом или рабочий процесс агента) и создала ли она измеримую ценность по сравнению с прежним методом.

Skill проектирует справедливый A/B-тест прежнего метода и метода после подключения новой возможности. По умолчанию используются три репрезентативные задачи из обычной работы пользователя или предоставленных им примеров. До запуска полный план проверяет человек. После выполнения создаётся автономный, визуальный и проверяемый HTML-отчёт.

## На какие вопросы он отвечает

1. **Была ли возможность действительно вызвана и где доказательство?**
2. **Создала ли она ценность и можно ли её измерить?**
3. **Можно ли визуально понять процесс использования и конкретную ценность?**

## Процесс

1. Определить новую возможность и методы до и после её подключения.
2. Выбрать три репрезентативные задачи из обычной работы пользователя.
3. В каждом раунде использовать одинаковые входы, требования к результату, правила остановки и критерии оценки.
4. Передать полный план человеку; при отклонении исправить и показать снова.
5. После явного одобрения выполнить оба метода в трёх раундах и записать результаты, метрики и доказательства вызова.
6. Проанализировать различия и создать HTML-отчёт.

Цель — не обеспечить победу новой возможности, а выяснить, что изменилось и достаточно ли доказательств для её принятия.

## HTML-отчёт

1. **Краткое решение**: сначала показывает оба метода, вывод, главную причину, вопрос о ценности и дату.
2. **Сравнение и анализ**: показывает сводные данные трёх раундов, результаты каждого раунда, наблюдения, внешние источники, преимущества, недостатки, конкретные сценарии и неопределённость.
3. **Дизайн и доказательства**: объясняет выбор задач, условия справедливости и критерии. Каждый раунд раскрывает две временные шкалы; вызовы моделей и инструментов и исходные журналы прикреплены к соответствующему шагу.

Недоступные метрики показываются как «Недоступно», а не как ноль. Секреты должны быть удалены.

## Ручное создание отчёта

```bash
python3 scripts/render_report.py tests/sample-experiment.json --output report.html
```

Рендерер использует только стандартную библиотеку Python и создаёт один HTML-файл, доступный без сети.

Последняя версия использует фиксированный формат отчёта с номером версии. Все отчёты сохраняют одинаковые разделы и порядок, а под каждым основным заголовком есть пояснение. Язык по умолчанию совпадает с языком общения пользователя и переключается в правом верхнем углу. Анализ отдельно показывает результаты эксперимента, внешние источники и итоговую рекомендацию, а сценарии описываются через конкретного пользователя, задачу и среду.

## Ограничения

- Три репрезентативные задачи уменьшают случайность одного запуска, но дают только доказательства в рамках этих задач.
- В каждом раунде оба метода должны использовать одинаковые входы и критерии.
- Token и стоимость сравниваются только при наличии данных от хоста.
- Если вызов невозможно подтвердить, вывод должен быть «Недостаточно доказательств».
- Headless-выполнение показывается как журнал, а не как прямая видеозапись.
