# Capability Value Test｜التحقق من قيمة قدرة جديدة

> اجعل استخدام القدرة الجديدة مرئيًا، والقيمة التي تحققها قابلة للقياس.

Capability Value Test هو Skill عام لوكلاء الذكاء الاصطناعي. يتحقق من أن قدرة مضافة حديثًا (مثل Skill أو نموذج أو إضافة أو MCP Server أو متصفح أو مكوّن مفتوح المصدر أو سير عمل للوكيل) قد استُخدمت فعلًا، ومن أنها تحقق قيمة قابلة للقياس مقارنة بالطريقة السابقة.

يصمم اختبار A/B عادلًا بين الطريقة السابقة والطريقة التي أصبحت ممكنة بعد إضافة القدرة الجديدة. يراجع الإنسان تصميم التجربة كاملًا قبل التنفيذ. وبعد الانتهاء يُنشئ تقرير HTML مستقلًا ومرئيًا وقابلًا للتتبع.

## الأسئلة التي يجيب عنها

1. **هل استُخدمت القدرة فعلًا، وأين الدليل؟**
2. **هل حققت قيمة، وهل يمكن قياسها؟**
3. **هل يمكن فهم عملية الاستخدام والقيمة الفعلية بصريًا؟**

## سير العمل

1. تحديد القدرة الجديدة والطريقتين قبل إضافتها وبعدها.
2. اختيار مهمة حقيقية تستطيع الطريقتان إنجازها.
3. توحيد المدخلات والبيئة والقيود ونطاق التوقيت ومعايير التقييم.
4. عرض تصميم التجربة كاملًا على الإنسان، وتعديله إذا رُفض.
5. تنفيذ الطريقتين فقط بعد الموافقة الصريحة، مع تسجيل النتائج والمقاييس وأدلة الاستخدام.
6. تحليل الفروق وإنشاء تقرير HTML.

الهدف ليس ضمان تفوق القدرة الجديدة، بل معرفة ما الذي تغير وما إذا كانت الأدلة تدعم اعتمادها.

## تقرير HTML

1. **التوصية النهائية**: اعتماد، عدم اعتماد، أو أدلة غير كافية، مع توضيح الحالات المناسبة وغير المناسبة.
2. **القيمة والفوائد**: جودة النتيجة، الزمن الكامل، Token، التكلفة، الخطوات، الأخطاء وإعادات المحاولة.
3. **إثبات الاستخدام**: يحتفظ القسم الأخير، لكل طريقة على حدة، بالأوامر واستدعاءات الأدوات والمدخلات والمخرجات والسجلات والطوابع الزمنية ومعرّفات المهام والحالات.

تُعرض المقاييس غير المتاحة على أنها «غير متاحة» وليس صفرًا. ويجب إزالة الأسرار والبيانات الحساسة.

## إنشاء التقرير يدويًا

```bash
python3 scripts/render_report.py tests/sample-experiment.json --output report.html
```

يستخدم المولّد مكتبة Python القياسية فقط وينشئ ملف HTML واحدًا يعمل دون اتصال.

يستخدم الإصدار الأحدث تنسيق تقرير ثابتًا وذا رقم إصدار. تحافظ جميع التقارير على الأقسام نفسها وترتيبها، مع شرح أسفل كل عنوان رئيسي. تكون اللغة الافتراضية هي لغة محادثة المستخدم ويمكن تغييرها من الزاوية العلوية اليمنى. يفصل التحليل بين نتائج التجربة والبحث الخارجي الموثق والتوصية النهائية، ويصف كل سيناريو من خلال مستخدم ومهمة وبيئة محددة.

## الحدود

- تشغيل واحد لكل طريقة يقدم دليلًا اتجاهيًا وليس ضمانًا إحصائيًا.
- يجب أن تتمكن الطريقتان من إنجاز المهمة التمثيلية نفسها.
- لا تتم مقارنة Token والتكلفة إلا إذا وفرهما النظام المضيف.
- إذا تعذر التحقق من الاستخدام فيجب أن تكون النتيجة «أدلة غير كافية».
- يُعرض التنفيذ دون واجهة رسومية كسجل تنفيذ، وليس كتسجيل مباشر.
