# Capability Value Test｜新しい能力の価値検証

[English](README.md)｜[简体中文](README.zh-CN.md)｜[繁體中文](README.zh-TW.md)｜**日本語**｜[한국어](README.ko.md)｜[Русский](README.ru.md)｜[हिन्दी](README.hi.md)｜[Español](README.es.md)｜[Français](README.fr.md)｜[Deutsch](README.de.md)｜[Português](README.pt.md)｜[العربية](README.ar.md)

> 新しい能力の利用プロセスを見えるようにし、その価値を測定可能にする。

Capability Value Test は、AI Agent 向けの汎用 Skill です。新たに統合した能力（Skill、モデル、プラグイン、MCP Server、ブラウザ、オープンソース部品、Agent ワークフローなど）が実際に呼び出されたか、従来の方法と比べて測定可能な価値を生んだかを検証します。

従来の方法と、新能力を統合した後の方法を公平な A/B Test で比較します。既定では、利用者の日常業務や提供された例から選んだ3つの代表的なタスクを実行します。実行前に人間が完全な実験計画を承認し、終了後に独立した視覚的で追跡可能な HTML レポートを生成します。

## 答えるべき3つの質問

1. **新能力は本当に呼び出されたか。証拠はどこにあるか。**
2. **本当に価値を生んだか。その価値を定量化できるか。**
3. **利用プロセスと具体的な価値を視覚的に理解できるか。**

## ワークフロー

1. 新能力と、統合前後の2つの方法を定義する。
2. 利用者が日常的に行う仕事から3つの代表的なタスクを選ぶ。
3. 各回で入力、出力要件、停止条件、評価基準を揃える。
4. 完全な実験計画を人間に提示し、却下された場合は修正する。
5. 明示的な承認後に両方式を3回実行し、結果、指標、呼び出し証拠を記録する。
6. 差分を分析して HTML レポートを生成する。

目的は新能力を勝たせることではなく、何が変わり、その証拠が採用を支持するかを確認することです。

## HTML レポート

1. **上部の判断要約**：両方式、結論、主な理由、価値の問い、実施日を最初に示します。
2. **主要比較と実験分析**：3回の集計、各回の結果、観察、外部資料、利点、欠点、具体的な利用場面、不確実性を示します。
3. **実験設計と証拠**：タスク選定理由、公平条件、判定基準を説明します。各回を展開すると左右のタイムラインが表示され、モデル・ツール呼び出しや原始ログは発生したステップに添付されます。

取得できない指標はゼロではなく「利用不可」と表示します。機密情報は必ず削除します。

## インストール

```bash
npx -y skills add EthanZhu-07/capability-value-test -g --all
```

またはリポジトリをクローンし、利用する Agent の Skill ディレクトリ規則に従って配置します。

```bash
git clone https://github.com/EthanZhu-07/capability-value-test.git
```

## 使用例

```text
Capability Value Test を使い、従来のブラウザ操作と Lightpanda 導入後の方法を比較してください。実行前に実験計画を提示してください。
```

## 手動でレポートを生成

```bash
python3 scripts/render_report.py tests/sample-experiment.json --output report.html
```

レンダラーは Python 標準ライブラリのみを使い、オフラインで開ける単一 HTML を生成します。

最新版では、バージョン付きの固定レポート形式を使用します。すべてのレポートは同じセクションと順序を保ち、各主要見出しの下に説明文を表示します。既定言語は利用者の会話言語で、右上から切り替えられます。分析では、実験結果、出典付きの外部調査、総合提案を分け、具体的な利用者・タスク・環境として利用場面を説明します。

## 制限

- 3つの代表的タスクは単発の偶然を減らしますが、結論はそのタスク範囲の方向性を示す証拠に限られます。
- 各回で両方式は同じ入力と判定基準を使う必要があります。
- Token とコストはホストが提供する場合のみ比較できます。
- 呼び出しを検証できない場合、結論は「証拠不足」です。
- ヘッドレス実行は実行記録として表示し、ライブ録画とは表現しません。
